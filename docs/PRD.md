# PRD — 模拟面试间

## 1. 问题

准备一场技术面试要干三件事：**读懂岗位**、**读懂这个人**、**想清楚要问什么**。

这三件事今天都发生在面试官脑子里，于是有三个后果：

1. **不可复用。** 同一个人面两个岗位，每个岗位都得从零读一遍 JD。
2. **不可留痕。** 问过什么、为什么问、候选人的回答是什么——散在记忆和聊天记录里，
   事后复盘只能凭印象。
3. **不对齐。** 面试官心里的「这个岗位要考什么」和真正问出来的东西，
   中间隔着临场发挥。

这个插件把三件事变成一条**可复用、可留痕、可对齐**的流水线。

## 2. 目标用户

| 角色 | 场景 | 插件给什么 |
|---|---|---|
| **求职者（自测）** | 面试前练一场，看看自己对目标岗位的准备够不够 | 按 JD 生成的针对性提问、逐题追问、不留情面的分析报告 |
| **面试官（主持）** | 线上面试时需要一个现场控制台 | 摄像头/录音、当前问题面板、转录留痕、考点清单的实时状态 |

两种角色共用同一套流程，差别只在 `role` 字段与措辞。

## 3. 主流程

```
        ① 准备                    ② 面试                    ③ 复盘
  ┌──────────────────┐    ┌────────────────────┐    ┌──────────────────┐
  │ 简历（上传/粘贴）│    │ 自我介绍            │    │ 逐考点评估        │
  │ JD（抓取/粘贴）  │───►│ 项目介绍            │───►│ 亮点 / 风险点     │
  │ 考点清单调研     │    │ 按清单提问          │    │ 清单调整回顾      │
  │                  │    │ 边问边调清单        │    │ 改进建议          │
  └──────────────────┘    └────────────────────┘    └──────────────────┘
         ▲                                                        │
         └──────────────── 手动兜底（抓取失败 / 文件读不出）─────┘
```

### ① 准备

- 简历：上传 `.txt` / `.md` / `.docx` / `.pdf`，或直接粘贴
- JD：给岗位链接自动抓，或粘贴正文
- 考点清单：模型用 `interview-prep` 技能做调研后落盘
- **岗位档案**：同一个岗位第二次面试，先继承上次的基线再做增量调研

### ② 面试

阶段固定，但**内容是活的**：

| 阶段 | 时长 | 内容 |
|---|---|---|
| 开场 | 1–2 分钟 | 说明规则、让候选人自我介绍 |
| 项目介绍 | 8–12 分钟 | 挑一个最有分量的项目系统讲一遍，确认职责边界 |
| 清单深挖 | 25–35 分钟 | 按 `core` → `deep` → `bonus` 推进，一次一问 |
| 收尾 | 5 分钟 | 候选人一问一评估、结束 |

**清单不是剧本。** 现场随时可以加（想到好问题）、删（不问了）、改（换角度）、
标记已问。每次调整都记理由，事后复盘能看到「为什么最后问了这些」。

### ③ 复盘

报告基于**转录原话**，不是通用套话。必须包含：结论、逐考点评估、
亮点、风险点、清单调整回顾、改进建议。

## 4. 功能清单

### 4.1 入场

| 功能 | 要求 | 验收 |
|---|---|---|
| JD 链接抓取 | 自动抓正文并切分职责/要求/加分 | 抓不到时返回明确原因 + 手动兜底提示，**不返回空正文当成功** |
| JD 手动兜底 | 粘贴文本 / 上传文件 | 任一路径都能存下 JD |
| 简历解析 | txt / md / docx / pdf / 粘贴 | 解析失败或乱码时明确告警 |
| 考点清单 | 分级 + 每项写明「为什么问」 | 清单在面板可见，且能反映已问/未问 |

### 4.2 现场

| 功能 | 要求 | 验收 |
|---|---|---|
| 摄像头 | 可开关，画面实时 | 权限被拒不阻断流程 |
| 录像 | MediaRecorder 录制，可保存到本机 | 保存后出现在列表里 |
| 录音 | 同上，可只录音 | 同上 |
| 语音播报 | 新问题自动朗读，可关 | 识别不到中文音色时用默认音色 |
| 语音识别 | **三级链路**：插件配置 → 继承宿主 → 浏览器原生 | 每一级都可用；继承不到时**明说原因**并回落 |
| 键盘输入 | 始终可用 | 识别不可用时照常作答 |
| 当前问题 | 实时显示助手最新一问 | 由 `interview_record_turn` 驱动 |
| 转录 | 逐轮留痕（谁问、谁答、几点） | 报告的唯一事实来源 |

### 4.3 岗位档案（历史复用）

| 功能 | 要求 | 验收 |
|---|---|---|
| 归档 | 一个岗位 = 一份 JD + 一份考点基线 | 档案可列出、可读、可删 |
| 继承 | 新面试一键继承档案的 JD 与清单 | 继承来的考点**被标记**为 `inherited` |
| 增量 | 在继承的基线上做增量调研 | 保留有效的、删过时的、加新的 |
| 回写 | 面试结束把成果写回档案 | 档案的清单与历场记录都更新 |

### 4.4 复盘

| 功能 | 要求 | 验收 |
|---|---|---|
| 分析报告 | 基于转录，含逐考点评估 | 报告里能引用到具体回答片段 |
| 统计 | 提问数、回答数、考点覆盖、清单调整次数、时长 | 面板可见 |

## 5. 边界与不做的事

- **插件不写面试题、不写报告。** 内容与判断归模型；插件负责状态与留痕。
- **插件不上传任何数据。** 简历、JD、转录、录像全在本机。
- **插件不发起付费生成。** 语音能力用浏览器原生 API。
- **插件不反爬。** 登录墙、验证码站点一律走手动兜底。
- **插件不做简历打分。** 它是面试工具，不是简历评估器。

## 6. 验收标准（整体）

1. `node scripts/build.mjs` 通过（语法 + 插件半边 + 运行时冒烟测试）。
2. 全新会话 → 上传简历 → 粘 JD → 模型产出考点清单 → 面板显示清单，
   全链路不需要手工改文件。
3. 面试中：开摄像头、录音、说话转写、提交回答——**其中任意一项失败都不阻断其余功能**。
4. 抓 JD 失败时，界面出现可操作的手动兜底提示，且能继续。
5. 结束后报告里能引用转录原话，且逐考点评估覆盖清单每一项。
6. 录像文件落在会话目录里，插件不向外部发送任何字节（除用户自己给的 JD 链接）。
