# 面试进行：提问、动态调整、事后分析

## 核心原则

> **考点清单是起点，不是剧本。**

清单是准备阶段的产物。面试是活的：候选人的回答会告诉你该往哪走。
所以每一轮之前都要重新看一眼清单和转录，**每一轮之后都可能要改清单**。

## 面试流程

### 阶段 0：开场（1–2 分钟）

- 说明这是模拟面试、会录音录像（如果开了）、可以随时喊停
- 让候选人**自我介绍**：请讲一段你认为最能代表你的经历
  - 自我介绍是**筛选题**，不是热身：听结构、听重点、听是否说得出结果与数据

### 阶段 1：项目介绍（8–12 分钟）

- 从简历里挑**一个**最有分量的项目，让候选人系统讲一遍
  - 提醒包含：背景与规模、你的角色、关键决策、结果数据
- 讲完后**不要立刻进入八股**。先确认一件事：你对这段经历**负责的那部分**是什么
- 这一步的目的是**建立共同语言**，后续所有深挖都挂在它上面

### 阶段 2：清单深挖（25–35 分钟）

- 从 `core` 级考点开始，按 JD 要求覆盖度推进
- **一次只问一个问题**，等回答完再问下一个
- 每个问题给**思考时间**（面试官不该抢答）
- 每个问题都落盘：`interview_record_turn`

### 阶段 3：收尾（5 分钟）

- 问一到两个 `bonus` 题（如果还有时间与对方状态）
- 让候选人提问——**听对方关心什么**，这是反向信息
- 结束：调 `interview_finish` 写报告

## 提问的质量标准

一个好问题有三个特征：

1. **挂在具体经历上**——"你简历里那个 800 万订单的项目，当时限流是怎么设计的？"
   而不是"讲讲高并发下的限流策略"。
2. **能引出判断**——问取舍、问当时还有什么方案、问为什么不用另一个。
   只问"是什么"的题，候选人背过就答得出来，问不出真假。
3. **允许说不知道**——如果候选人说不知道，**追问一句为什么不知道**
   （是没做过、是当时没参与、还是没想清楚）。这三种答案含义完全不同。

## 动态调整清单（重要）

每一轮之后，判断是否要动清单，并用 `interview_mutate_checklist` 记录：

| 现场情况 | 动作 |
|---|---|
| 候选人把某考点**答穿了**（细节、代价、数据都在） | `probe` 标记已问；`add` 一个更深的追问点 |
| 候选人**答不上来**且简历里确有这段经历 | 降级追问，或 `remove` 掉这个考点——一个答不上的点问三遍只是折磨 |
| 候选人主动提到**清单里没有**但很有价值的方向 | `add` 进去，记 `reason` 说明为什么加 |
| 候选人讲的经历**与 JD 完全无关** | `remove` 掉相关考点，把时间给对得上的 |
| 候选人的回答暴露了**新的风险点** | `add` 一个针对性问题 |

**每一次调整都要写 `reason`**——它会进 `adjustments[]`，事后复盘时能看出
"为什么最后问了这些"。不写理由的调整没有价值。

## 记录纪律

- 你问的每一句 → `interview_record_turn`（role: `interviewer`）
- 候选人的每一段回答 → `interview_record_turn`（role: `candidate`）
  - `meta` 里记 `topicId`（关联考点 id）与 `asr`（识别置信度，如果有）
- **不要**把转录写在对话里就完事。插件的转录是报告的唯一事实来源。

## 事后分析报告

调 `interview_finish` 时给出 Markdown 报告，包含：

1. **结论**：整体评价（建议评级 / 是否推进），三句话以内
2. **逐考点评估**：清单每一项 → 命中情况（深挖到位 / 答得含糊 / 没答上来）+ 一句证据
3. **亮点**：具体到哪段经历、哪个决策
4. **风险点**：具体到哪个要求、哪里没接住
5. **清单调整回顾**：现场改过哪些考点、为什么（从 `adjustments[]` 读）
6. **如果重来**：给候选人的 2–3 条改进建议

**报告必须基于转录里的原话**，不要写通用套话。引用具体的回答片段
（可以匿名化），比任何评价词都有说服力。

## 收尾时：回写岗位档案

报告写完之后，如果这场面试是**某个岗位的正式面试**（而不是随手练一场），
把成果沉淀下来：

1. `interview_sync_profile` —— 把当前 JD、最终考点清单、这场面试的记录
   回写进岗位档案。
2. 档案里的清单**就是下一场的基线**：下一场面试用 `interview_apply_profile`
   继承它，再做增量调整。

**先问一句再回写。** 如果用户没说这是哪个岗位，就问；不要把一场随手练的
面试塞进某个档案里污染基线。

同时告诉用户沉淀结果：这场面试最终问了几项、覆盖了 JD 的哪几条、
**哪几条没覆盖到**（这才是下一次调研要补的地方）。
